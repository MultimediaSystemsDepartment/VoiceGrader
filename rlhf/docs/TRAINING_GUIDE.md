# Training Guide

End-to-end walkthrough for fine-tuning Whisper Large-v3 on Polish speech with human preference feedback.

Default policy state is isolated under `_outputs/large-v3/`. Keep Medium
databases/adapters separate and align paths and policy configs when explicitly
resuming another lineage. The reward encoder remains Medium. Microbatch defaults
are conservative, not a verified GPU capacity result. Use the root
[VoiceGrader README](../../README.md) for image builds and GPU maintenance windows.

---

## Prerequisites

1. Python environment with all dependencies installed (see [README.md](../README.md)).
2. `default_paths.json` configured with valid path to the ADMEDVOICE manifest CSVs (generated by `prepare_data.py`).
3. An NVIDIA GPU (RTX 3090 or equivalent recommended).

Verify config:
```
py -c "from paths import DEFAULT_PATHS; print(DEFAULT_PATHS)"
```

## Round 0 — Bootstrap (First Run)

### Step 1: Build the audio catalogue and generate pairs

```
py run_generate_pairs.py --datasets admedvoice --n 200
```

This:
- Reads CSVs, validates audio files, populates `audio_files` table.
- Runs one deterministic beam pass plus temperature sampling to produce 6 candidates per clip by default.
- Cold start (no reward model yet): pairs the beam result with the most dissimilar sample.
- With reward model: scores all N candidates and pairs the best vs worst by maximum reward gap (RSO).
- Inserts pairs with `status='pending'` into `hypothesis_pairs`.

Adjust `--n` to control how many pairs to generate and `--n_candidates` to change the candidate count. After the first DPO run, the active LoRA policy is loaded automatically.

### Step 2: Annotate

```
docker compose -f ..\compose.yaml up rlhf training
```

Annotators open `http://localhost:8080`, enter a participant ID, and work from
the browser. The web service signals refill when the pending queue is low; the
coordinator performs GPU generation.

### Step 3: Train the reward model (needs ≥ 50 actionable annotations)

```
py run_train_reward.py
```

Trains the MLP head (Whisper encoder and BERT remain frozen) with Bradley-Terry pairwise loss. Checkpoint saved to `_outputs/large-v3/reward_model/reward_model_v1/`. Skipped automatically if not enough annotations — re-run after more annotation.

### Step 4: Generate current-round synthetic DPO data

```
py run_generate_synthetic.py --round_id vMANUAL --output _outputs/large-v3/tmp/dpo_rounds/vMANUAL/synthetic_pairs.jsonl --rm_checkpoint _outputs/large-v3/reward_model/reward_model_vMANUAL
```

Generates a large randomized candidate pool from the exact DPO start policy and ranks candidates with the current reward model. The JSONL artifact is temporary and does not enter SQLite. Normal operation delegates versioned paths and cleanup to the coordinator.

### Step 5: SFT on human corrections

```
py run_sft.py --epochs 3
```

Fine-tunes Whisper on transcripts where annotators typed a correction. Establishes a better starting checkpoint before DPO.

### Step 6: First DPO fine-tuning pass

```
py run_rlhf.py --resume _outputs/large-v3/checkpoints/sft --reference _outputs/large-v3/checkpoints/sft --synthetic_data _outputs/large-v3/tmp/dpo_rounds/vMANUAL/synthetic_pairs.jsonl
```

This:
1. Evaluates WER for the actual starting policy (SFT/active adapter, not always base Whisper).
2. Loads authoritative human A/B choices and capped current-round synthetic choices.
3. Fine-tunes Whisper with LoRA r=16 on every `q_proj` and `v_proj` (encoder self-attention and decoder self/cross-attention) using DPO loss.
4. Evaluates the fine-tuned model.
5. Saves LoRA checkpoint to `_outputs/large-v3/checkpoints/whisper_dpo_TIMESTAMP/`.
6. Records the full run in `training_runs` table.
7. Publishes the checkpoint as `active_policy_checkpoint`, retires stale pending pairs, and queues refill.

Expected duration is dominated by synthetic generation and depends on `synthetic_pool_size` and candidate count.

## Round 1+ — Iterative Improvement

After the first fine-tuning round:

### Collect more annotations (with the updated model)

Regenerate pairs — generation automatically attaches the active Whisper policy, while the coordinator supplies the latest reward-model checkpoint for candidate ranking:

```
py run_generate_pairs.py --n 200
# Continue annotation at http://localhost:8080; refill is automatic.
```

### Retrain the reward model periodically

As more annotations accumulate, retrain the AudioTextRewardModel to keep the reward signal up to date. Bump `reward_model_version` in `config/reward_model_config.json` before each run to keep checkpoints versioned:

```
py run_train_reward.py
```

### Track progress

```
py run_evaluate.py --report
```

Prints a table of all training runs with WER before/after each round:

```
RLHF Training History
========================================================================
Run   Algorithm     ADMED WER Δ  Annotations          Started
------------------------------------------------------------------------

2     dpo             -1.54pp   400h/0s    2026-06-29T10:00
3     dpo             -2.10pp   600h/200s  2026-06-30T10:00
```

## Troubleshooting

**"Only N DPO pairs available"**
Collect more human A/B choices or regenerate the current-round synthetic artifact. The coordinator performs both checks automatically.

**"Synthetic generation produced no confident DPO pairs"**
The reward gaps were below threshold or candidates collapsed. Try:
- Running more annotation sessions to get clearer human preferences.
- Training the reward model with more human choices.
- Generating more candidates or lowering `reward_gap_threshold` cautiously.

**CUDA out of memory during RLHF training**  
Reduce `batch_size` in `config/rlhf_config.json` (try 2) and increase `gradient_accumulation_steps` proportionally (try 16). The effective batch size = batch_size × gradient_accumulation_steps; keep it at 32.

**CUDA out of memory during reward scoring**
The AudioTextRewardModel uses ~2.5 GB VRAM. If you are still OOM, ensure no Whisper process is active at the same time and reduce `batch_size` in `config/reward_model_config.json`.

**Audio file not found during evaluation**  
`default_paths.json` may have paths that differ from what was stored in the DB (e.g., if you moved audio files). Re-run `py run_generate_pairs.py --catalogue_only` to refresh the catalogue.

## Configuration Reference

| File | Controls |
|------|---------|
| `default_paths.json` | Data paths (audio dirs, CSV paths) |
| `config/inference_config.json` | Whisper model, batch size, decoding strategies |
| `config/reward_model_config.json` | AudioTextRewardModel: BERT/Whisper IDs, MLP dims, training hyperparameters |
| `config/rlhf_config.json` | Algorithm, LoRA, learning rate, KL coef, DPO beta |

All configs support JSON round-trip. Edit the file and pass via `--config` flag to any entry point.
