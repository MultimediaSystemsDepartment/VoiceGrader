# VoiceGrader

Development archive bringing together ASR annotation, training and inference.
One repository and one Compose project package the following components:

| Directory / service | Role | Image |
| --- | --- | --- |
| `rlhf/` / `rlhf` | CPU annotation and administration UI; shared RLHF source | `voicegrader-rlhf:dev` |
| `training/` / `training` | GPU coordinator, generation, reward training, SFT/DPO and evaluation | `voicegrader-training:dev` |
| `asr/` / `asr` | Existing file/live transcription and audio-quality service | `voicegrader-asr:dev` |
| `tts/` / `tts-api`, `tts-piper` | Authenticated local synthesis API and separate CPU Piper engine | `voicegrader-tts-api:dev`, `voicegrader-tts-piper:dev` |

Containers are separate processes with separate dependency environments, not
threads or separate required machines. Compose connects them on one host.
The web and training images use the same `rlhf/` source tree; training logic is
not duplicated in `training/`.

## Quick start

Use Linux or Docker Desktop with a WSL2 Linux backend and NVIDIA GPU support.
Image builds download dependencies and model weights and need substantial disk
space. The inherited ASR build also fetches WhiSQA from its upstream repository.

From this repository root:

```powershell
Copy-Item .env.example .env
docker compose --profile training config --quiet
docker compose --profile training build
docker compose up -d rlhf asr tts-piper tts-api
```

- Annotation/admin: <http://localhost:8080>
- ASR: <http://localhost:8000>

Port changes are available in `.env`. Compose configuration validation does not
build images or start containers.

### Training maintenance window

The admin refill button queues a request; the CPU web does not execute it.
An absent training worker leaves it queued. Duplicate browser requests display
an admin-page notice rather than JSON; API clients retain HTTP 409.
Approved recordings must also be imported and activated before generation.
Already-paired recordings cannot supply new work for the same deployed policy;
refill requires additional eligible recordings or a subsequently activated policy.

**Local annotation session (2026-11-23):** normal coordinator enabled, ASR
paused, auto-refill minimum 20 and batch 50. A separate active corpus contains
100 additional short recordings; the original six annotations were preserved.
The first automatic cycle produced 30 distinct pairs from 50 recordings
(20 had identical candidates and were correctly omitted). All 30 audio
responses were verified as playable mono 16-kHz WAVs. Further refill is automatic
below 20 pending pairs. The operator raised automatic training to 100
annotations; deployment still requires a ready frozen WER Monitor and passing gate.
TTS learning shares remain 0%. The source archive and prior proof holdout are
unchanged. This is a bounded annotation pool, not an unlimited source of pairs.

The coordinator can generate pairs automatically, not only when training is
manually requested. On the development GPU, keep ASR and GPU learning stages
separate until their combined memory use is measured. The `training` profile is
opt-in so a default `docker compose up` does not start GPU learning.

Place approved source data in `_data/rlhf/` and configure
`rlhf/default_paths.json`. For the existing ADMEDVOICE importer, the coordinator
can prepare manifests from `_data/rlhf/archive.zip`.

### Adding training or evaluation recordings

Open **Audio Corpora** (`/admin/corpora`) and choose **Training corpora** or
**Evaluation sets**. Supply a new corpus name, a UTF-8 semicolon-separated CSV,
and the audio files referenced by that CSV:

```csv
file_path;transcript
recording-001.wav;Correct Polish transcript.
recording-002.wav;Another verified transcript.
```

Use plain filenames, not host paths or directories. Uploads support 1-200 clips
of 0.1-30 seconds, at most 500 MiB total and a 1 MiB manifest. Archives and
standalone text uploads are not supported in this browser workflow. Transcripts
are optional for training but mandatory for evaluation. Validation checks
decoding, duration, manifest membership, duplicate normalized audio content and
holdout/learning overlap; it does not establish transcript accuracy or detect
all near-duplicates. Invalid uploads are rejected without partial DB imports.

Listen in the preview, then **Accept import** or **Cancel**. Uploaded files
persist under the shared `_data/rlhf/corpus_uploads/` directory.
Training imports stay inactive until explicitly enabled. Evaluation imports
create an editable WER Monitor draft and cannot be enabled for learning, even
if the draft is removed. Review/copy and correct the reference transcripts in
WER Monitor, then freeze. Freezing queues baseline evaluation; select the desired
frozen set as the promotion gate explicitly.

DPO before/after evaluation automatically uses the designated frozen WER
Monitor, with all its verified clips and deterministic Polish beam-5 decoding.
No CSV export or additional data preparation is required. The reference snapshot
is pinned across the round and its fingerprint participates in baseline caching.
For database compatibility, this primary-domain WER remains stored in the
existing `wer_*_admed` training-run columns; evaluator output labels it
**WER Monitor**. An optional configured Common Voice benchmark remains separate.
Without a frozen gate, the existing configured CSV evaluation path remains
available, but automatic promotion still requires the frozen monitor.

Reusing the monitor for reports and promotion is not independent quality
confirmation. Keep a separate benchmark for release certification, and do not
repeatedly tune against a held-out set and then claim unbiased test results.

The new default policy paths do not modify an existing Medium database or
checkpoint directory. Do not copy Medium adapters into the Large-v3 lineage or
relabel old feedback. To resume Medium work, explicitly align the policy configs
and all paths with its original state. Policy microbatch defaults are now one,
with DPO accumulation of 32; this preserves the effective batch size, but is not
a measured GPU-capacity guarantee.

```powershell
docker compose stop asr
docker compose up -d rlhf training
docker compose logs -f training
```

An explicitly named service starts even when it has a profile. When generation
or training has completed, stop the coordinator before restoring ASR:

```powershell
docker compose stop training
docker compose up -d asr
```

Do not interrupt an active training round merely to switch services. Automatic
GPU scheduling and inference request draining are future work.

For a host with sufficient GPU capacity, all three can be requested together:

```powershell
docker compose --profile training up -d
```

This is not a guarantee that concurrent workloads fit a 24-GB GPU.

## TTS Augmentation Campaigns

Open **TTS Augmentation** in the admin UI (`/admin/tts`). Create a
**TTS Augmentation Campaign** by selecting an active corpus,
intended use (SFT, annotation, or both), engine/voice profiles and count,
cumulative coverage, or all eligible utterances. Preview before creation.
Campaign membership and provider origin are frozen; existing combinations are
reused. Changing `TTS_BASE_URL` affects new campaigns, not existing ones.

The CPU web service processes persisted campaigns independently of the GPU
training coordinator. Campaign submission, polling and audio import continue
while `training` is stopped and ASR is running for quality review. No local
synthesis model or ML subprocess runs in the web service.

For an explicit bounded worker tick:

```powershell
docker compose exec -T rlhf python run_tts_worker.py --max-items 1
```

This command does not wait for completion; the normal web dispatcher continues
polling/downloading ready items afterward.
It contacts each explicitly created campaign's frozen provider. The local adapter
uses authenticated `/v1/jobs` (HTTP 202) and checksum-verified ZIP manifests;
the legacy external adapter retains `/api/v1/tts/jobs`. Only Piper has been
live-tested; GPU profiles remain unverified.

Accepted job IDs persist across restarts. Ambiguous submissions require operator
review: attach a known job ID, cancel local work, or explicitly acknowledge
duplicate risk before retrying. A known local HTTP 429 rejection can retry with
bounded backoff and the same request ID; ambiguous POST outcomes never retry
automatically. Explicit new synthesis alone changes that request ID.
Cancellation cannot cancel accepted remote jobs; their results remain collectible.
Failed/expired results and download/validation errors remain visible.
Each recording has its own responsive review card. **Retry collection** reuses
the existing provider job and never requests new synthesis. **Submit new synthesis**
is a separate explicit action: its hover/focus warning explains duplicate work
and possible extra cost, without a repeated acknowledgement checkbox. Backend
duplicate-risk validation remains enforced. Quality scores are shown as readable
metrics; raw results and technical/audit details are collapsed by default.

Set separate SFT/refill percentages on the campaign page when participation is
desired. They are maximum shares, not targets, and start at 0%. SFT selects at
most one TTS rendition per utterance per epoch. Permitted requested text can be
an SFT target; DPO labels still require actual human choices or the existing
separately capped temporary preference-generation stage. Monitor-linked
utterances/text remain excluded, and snapshots retain synthesis provenance.

The root Compose file is the supported deployment; the copied laboratory

at most 280 characters; campaign estimates explicitly count excluded longer
texts, without truncating the source. Imports still require native 0.1-30-second,

### Report-only synthesized-audio quality review

Completed campaign items offer **Assess quality**. The CPU web dispatcher sends
the normalized recording to the configured local `VOICEGRADER_ASR_URL` using the
independent service credential; it never loads WhiSQA or starts an ML subprocess.
ASR reuses its SNR/Silero and multidimensional WhiSQA workers without running
transcription. Scores include estimated MOS, noise/discontinuity/coloration/loudness
and available speech/noise statistics. Missing SNR is shown as null, not zero.

Requests, results, errors and human review notes persist in SQLite. Use
**Mark reviewed** after listening; low scores never automatically reject,
quarantine or change a recording's learning eligibility or participation caps.
MOS measures predicted acoustic quality, not correctness of the requested text.
Failed/offline requests require explicit retry; there is no remote TTS submission.
The scorer profile is recorded with each result.

For the development GPU, stop `training` before starting `asr`; the web quality
dispatcher works with the training coordinator stopped. Stop ASR before restoring
training afterward. The application does not automatically schedule these GPU
windows. For separate hosts, configure the local ASR URL and provision the same
service credential securely; use HTTPS across untrusted networks.

## Approved model bridge

Publication runs only in the training image, after a passing policy gate or
when an idle worker detects an approved rollback. Publication failures have
separate status/logs and do not retrain or activate a candidate. Retry explicitly:

```powershell
docker compose run --rm --no-deps training python3.12 run_publish_model.py --if-ready
```

Conversion and its WER check require a GPU maintenance window. The web exposes
authenticated metadata/artifacts at `/api/model-publication`; it never converts
models. Immutable identities and checksums also let rollback propagate.
Source weights changing after publication are rejected rather than silently reused.

ASR checks at startup and retains installed artifacts when delivery fails.
With no approved publication, stock Large-v3 is an explicit normal bootstrap.
With Compose's `VOICEGRADER_HOT_RELOAD=1`, it also checks for approved publications
every 60 seconds. A new identity starts a drained reload:

1. Stop admitting new file jobs, quality requests and live sessions (HTTP 503 with
   `Retry-After`, or WebSocket close 1013); existing work continues.
2. Wait for active requests/sessions **and submitted worker tasks** to finish.
   The default 300-second drain deadline aborts without disconnecting them.
3. Stop model workers, download/verify/load-test the update, then start the file
   and live workers with the same pinned model. The HTTP service stays running.
4. Report the new loaded identity only after readiness. If loading fails, restore
   the previous installed pointer and workers; if recovery fails, remain unavailable
   rather than accepting work into a broken runtime.

An authenticated `POST /api/model-publication/reload` on ASR explicitly retries
or requests a reload (202 accepted; 409 if already running). Use the bridge service
credential, not the human admin password. Failed identities are not automatically
retried every poll. Existing live sessions are not migrated mid-stream.
Set `VOICEGRADER_HOT_RELOAD=0` to disable polling; manual reload remains available.

The older download/restart path remains available, but requires enough spare
GPU memory for its pre-switch load test:

```powershell
docker compose exec asr python -m asr_processor.model_update
docker compose restart asr
```

New downloads are load-tested with CUDA/float16 before the pointer changes.
ASR's `/api/model-publication` reports loaded/downloaded identities, restart
requirements, update errors and reload/drain/availability status.
Previous immutable model directories are retained. Run one ASR HTTP process per
instance: admission and worker ownership are process-local.

Compose creates a separate random service token in the persistent `bridge_auth`
volume; ASR reads it through a read-only mount. It is not the admin password.
For separate hosts, configure `VOICEGRADER_RLHF_URL` with HTTPS, securely provision
the identical token file in ASR's read-only mount, and adjust the local Compose
dependency/start ASR with `--no-deps`. Never commit or publish the credential.

## Persistence and packaging

- `_data/rlhf/` is machine-local, ignored input/manifests storage.
- `rlhf_outputs` is a shared local Docker volume for the feedback database,
  checkpoints, logs and current adapter publication, now under `large-v3/`.
- `rlhf_model_cache` preserves RLHF/training Hugging Face model downloads.
- `asr_models` and `asr_cache` preserve ASR model downloads separately.
- `bridge_auth` preserves the independent HTTP bridge credential.
- Input data, credentials, model weights and runtime databases are not part of
  the source archive. Back them up separately where authorized.
- Avoid `docker compose down --volumes`: it deletes named runtime volumes.
- No Docker socket is mounted into any application.
- Source is copied into images, not bind-mounted. Source changes require an
  image rebuild; normal restarts alone do not update this packaging.

Use only the root Compose project for this ecosystem. Imported deployment
files remain historical upstream references, not an alternative VoiceGrader
configuration. The RLHF GPU Dockerfile was relocated to `training/Dockerfile`.

## Generic recorded-audio imports

The first workflow is CLI-only: local files or ZIP members plus a UTF-8 CSV.
Use exactly `file_path` and an optional `transcript` column, separated by `;`
unless `--delimiter` specifies another character. For example:

```csv
file_path;transcript
clips/001.wav;Example reference transcript.
zip:recordings.zip!clips/002.wav;
```

Paths are relative to `--audio-root`, or to the manifest directory by default.
ZIP member names use `/`; archives are read without extraction. Audio must have
a readable soundfile header, decode successfully through the shared loader,
contain finite samples and last 0.1-30 seconds. Segment longer recordings first.
Files are not copied, rewritten or resampled on disk. Duration and sample-rate
metadata describe the original file. An import references the source files;
keep their paths and contents stable.

Host examples, run from `rlhf/`:

```powershell
py -3.12 run_import_corpus.py import --name example --manifest _data\corpora\example\manifest.csv --dry-run
py -3.12 run_import_corpus.py import --name example --manifest _data\corpora\example\manifest.csv
py -3.12 run_import_corpus.py list
py -3.12 run_import_corpus.py activate --name example
py -3.12 run_import_corpus.py deactivate --name example
```

`--db <path>` before the subcommand selects another database. The default uses
the configured Large-v3 lineage. `--dry-run` validates files without opening or
creating a database; existing-record conflicts are checked during actual import.
Commands emit JSON reports and return nonzero on failure. Any invalid row
rejects the entire import; corpus/asset registration is atomic.

New corpora are inactive. Activation enables existing selection rules, not
automatic GPU execution; Polish/monitor/curation exclusions still apply.
Clips without reference text can enter annotation generation but cannot serve
as TTS source text or ground-truth labels. Synthesized audio remains disabled.
Deactivation blocks future selection, not already-running training inputs.
Reimports skip identical paths with compatible corpus/text identity; conflicts
never overwrite transcripts. Deactivate before appending new recordings.

For Docker, place sources in `_data/rlhf/corpora/` at the repository root and
import using paths visible inside the container, **not host absolute paths**.
After separately approved image builds, this example runs only the importer,
not the coordinator or dependent services:

```powershell
docker compose run --rm --no-deps training python3.12 run_import_corpus.py import --name example --manifest /app/_data/corpora/example/manifest.csv
docker compose run --rm --no-deps training python3.12 run_import_corpus.py activate --name example
```

Project-local sources are stored with portable project-relative paths; external
sources retain runtime-specific absolute paths. Consumers of relative paths
must run from the RLHF project root, as the existing worker does.
Browser uploads, standalone text imports, automatic
downloads, physical deletion and fuzzy/content-based deduplication are outside
this first slice. Existing ADMEDVOICE/Common Voice importers are unchanged.
